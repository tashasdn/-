# PUSHKINS COFFEE · Telegram Mini App

Русскоязычная витрина кофейни: категории, поиск, объём напитка, молоко, корзина с сохранением, самовывоз и комментарий. Адаптирована для телефонов и Telegram.

**Сейчас включён деморежим. Меню и цены примерные. Заказы не отправляются, деньги не списываются.** Серверная часть для Telegram Payments подготовлена отдельно и ещё не подключена к реальному боту/провайдеру.

## Посмотреть локально

Нужен Node.js 24+. Из папки `pushkins-coffee`:

```bash
node scripts/preview.mjs
```

Откройте http://127.0.0.1:4173. Не открывайте HTML двойным щелчком: ES-модулям нужен HTTP-сервер.

## GitHub Pages

Если проект лежит в общей папке `pushkins-coffee`, в корне репозитория предусмотрена стартовая страница, ведущая на `pushkins-coffee/docs/`.

В GitHub откройте Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save. После успешного размещения ссылка для этого репозитория:

`https://tashasdn.github.io/-/pushkins-coffee/docs/`

Это ожидаемый адрес, а не подтверждение, что Pages уже включён. Для бота используйте прямой адрес выше. Все пути относительные и подходят для project Pages.

Если размещаете только этот проект в отдельном репозитории без общей папки, выбирайте `main` → `/docs`.

## Изменить меню и информацию

Один файл: `docs/catalog.js`.

- `shop.address`, `shop.hours`, `shop.supportUrl`: реальные данные кофейни;
- `products`: названия, описания, размеры, цены в рублях, доплата за молоко;
- `shop.apiUrl`: пустая строка сохраняет деморежим; адрес HTTPS API включает настоящую оплату.

Фотографии сейчас иллюстративные, с Unsplash; шрифты загружаются с Google Fonts. Замените фотографии на собственные и при необходимости храните ассеты локально. Если фото товара недоступно, показывается встроенная иллюстрация.

## Подключение Telegram и оплаты

GitHub Pages обслуживает только статические файлы. API из `backend/` нужно разместить отдельно на сервере с Node.js 24+, постоянным диском для SQLite и публичным HTTPS. Для одного небольшого экземпляра приложения зависимости npm не нужны.

1. Создайте бота через @BotFather. Подключите доступного вашему бизнесу провайдера через раздел Payments. Получите `BOT_TOKEN` и `PROVIDER_TOKEN`. Для кофе используется обычная валюта `RUB`, не Stars.
2. Скопируйте проект на сервер. Создайте `backend/.env` по образцу `backend/.env.example` **только на сервере**. Токены не вставляются в HTML, `catalog.js` или GitHub.
3. Впишите `APP_URL` (адрес Pages), `API_URL` (HTTPS API), `FRONTEND_ORIGIN=https://tashasdn.github.io` (без пути и завершающего слеша). `ADMIN_CHAT_ID` — чат бариста, где бот имеет право писать. Запустите бота в личном чате либо добавьте его в нужную группу.
4. Сгенерируйте `WEBHOOK_SECRET` командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` и сохраните в серверном `.env`.
5. Перед реальным приёмом платежей настройте в `backend/server.mjs` данные чека (`provider_data`, необходимые поля покупателя) по требованиям именно вашего эквайринга. Этот шаблон не содержит готовой фискализации, оферты и политики обработки данных. Договор с провайдером и конфигурация кассы остаются за владельцем кофейни.
6. Запустите `node --env-file=backend/.env backend/server.mjs`. Настройте автозапуск, резервное копирование `data/` и HTTPS reverse proxy на `127.0.0.1:8787`. Внешний API должен быть доступен посетителям кофейни. SQLite требует постоянного локального диска; не запускайте несколько независимых копий API с разными базами.
7. Выполните `node --env-file=backend/.env scripts/setup-bot.mjs`. Скрипт установит webhook и кнопку «Заказать кофе» в меню бота. В настройках Mini App в BotFather укажите тот же домен Pages.
8. Задайте `shop.apiUrl` в `docs/catalog.js` и обновите Pages. После изменений меню обновляйте и файлы сервера: он использует тот же каталог для проверки цен.
9. Пройдите полный цикл с тестовым режимом провайдера: создание счёта, отмена, успешная оплата, повтор webhook, сообщение бариста и восстановление статуса после перезапуска. Затем переключайте провайдера в рабочий режим.

Сервер проверяет подпись и срок действия `initData`, владельца заказа, состав и стоимость, валюту и сумму подтверждённого платежа. Заказы и идентификаторы платежей сохраняются в SQLite. Повтор запроса с тем же `requestId` возвращает прежний заказ. Только `successful_payment` от webhook меняет статус на `paid`; ответ интерфейса Telegram сам по себе не считается оплатой.

Заказы поступают бариста в Telegram. Полноценная панель бариста, стоп-лист, автоматическая оценка готовности, доставка, возвраты из интерфейса и программа лояльности в этот MVP не входят. Сроки хранения заказов и удаление персональных данных необходимо настроить перед запуском.

## Проверки

```bash
node --test backend/core.test.mjs
```

Проверяются подпись Telegram, отклонение изменённых/просроченных данных, расчёт цен на сервере, неверные позиции и соответствие платежа заказу. Настоящие платежи без бота и договора провайдера не проверялись.

Официальная документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Payments](https://core.telegram.org/bots/payments), [Bot API](https://core.telegram.org/bots/api#createinvoicelink).
